## 3. The trap that broke production, and why green CI did not catch it

Commit `44509b17` changed the `columnSpec` query to:

```php
'select ... where table_schema = database() and table_name = ?
   and extra not like '%auto_increment%'',
```

`php -l` passed. CI passed. Production broke with
`Undefined constant "App\Concerns\auto_increment"`.

Why: in a single-quoted PHP string the `'` before `%auto_increment%` closes the
string. The rest is then valid syntax — `string % auto_increment % string` is a
modulo expression — so the parser is happy and only runtime fails.

The current fix binds the pattern instead, so no quote is ever embedded:

```php
'... and extra not like ?', [$table, '%auto_increment%']
```

**Rule:** for SQL, `php -l` proves nothing. Run the query against MySQL, or bind
every literal.

## 4. Traps found today, listed so they are not repeated

| `Schema::getColumns()` | Does not exist in Laravel 10. Use `information_schema`. |
